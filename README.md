# agent-loop

**Автономный прогон по плану проекта — который не врёт, что работает.**

Навык для Claude Code. Ставится на расписание, каждый тик берёт один пункт плана,
делает его и записывает состояние. Не закрывает работу без доказательства и не
будит владельца по мелочам.

> *A Claude Code skill for unattended, scheduled work against a project plan.
> One item per tick, state written every tick, three outcomes instead of two —
> and it never records "done" without proof. Interface and output are in Russian.*

---

## Зачем

Автономный прогон ломается не там, где ждёшь. Он ломается **тихо**: снаружи всё
живо — сессия открыта, задача в расписании есть, — а работы нет.

Замер на настоящем прогоне, корреляция без единого исключения:

| разрыв между тиками | сколько длился ход перед ним |
|---|---|
| ровно 30 мин (шаг) | 0–2,8 мин |
| 68 мин | 41 мин |
| 66 мин | 60 мин |
| 75 мин | 55 мин |

**Тик, который работает дольше шага, съедает следующий**, а пропущенный не
догоняется. Владелец видит открытую сессию и живое расписание — и не видит, что
половина ночи прошла впустую.

Поэтому в навыке записано: тик обязан уложиться в шаг, не помещается — дели
пункт. И судить о жизни прогона надо по **растущему файлу состояния**, а не по
наличию задачи в расписании.

---

## Три правила, на которых всё держится

**Исхода три, а не два.** Сделано · сломано · **не проверено**. «Не знаю»
никогда не становится зелёным.

**«Готово» имеет право стоять рядом только с доказательством** — хешем коммита,
который резолвится, кодом возврата команды, живым адресом, листингом файла.
«Должно работать» — это «не проверено», так и пишется.

**Отрицательный результат ничего не значит, пока зонд не доказал, что видит.**
Прежде чем поверить в «чисто» — подложи заведомую поломку и убедись, что
покраснело.

## Установка

Нужен Claude Code со встроенным навыком `/loop` — он идёт в поставке, ставить
отдельно ничего не надо.

```bash
mkdir -p ~/.claude/skills/agent-loop
cp skill/SKILL.md ~/.claude/skills/agent-loop/
```

Проект, по которому пойдёт прогон, должен иметь `CLAUDE.md` и `PLAN.md`. Плана
нет — навык честно скажет «брать нечего» и остановится, а не выдумает работу.

### Проверьте установку до того, как доверить ночь

Своей команды самопроверки у навыка нет — он живёт внутри сессии. Проверяется
коротким прогоном на песочнице:

```bash
mkdir -p /tmp/проба && cd /tmp/проба && git init -q .
cat > CLAUDE.md <<'EOF'
# Проба
Песочница. Ничего за пределами папки не трогать.
EOF
cat > PLAN.md <<'EOF'
# План
## Очередь на сейчас
Нужен файл `итог.txt` со словом «раз» внутри.
Нужен файл `число.txt`, в нём — сколько строк в этом плане, посчитать командой.
EOF
git add -A && git commit -qm первый
```

Запустите в этой папке Claude Code, скажите «запускай луп с шагом 2 минуты» и
смотрите. Что должно случиться:

1. навык поднимется сам и покажет заведённую задачу расписания;
2. первый тик соберёт очередь в файл состояния — **файлы проекта не тронет**;
3. следующие тики создадут два файла и запишут отчёт о каждом тике.

Не случилось — разбирайтесь до того, как ставить прогон на ночь.

## Как пользоваться

Скажите в сессии внутри проекта: «запускай луп», «поставь луп на ночь»,
«продолжай сам». Шаг по умолчанию 30 минут; назовёте свой — возьмёт ваш.

**Держите строку ввода пустой.** Расписание срабатывает только между ходами, на
простаивающей сессии.

---

## Что он делает и чего не делает

**Делает:** собирает очередь из прозаического плана (в том числе со врезками
«эта очередь устарела»), берёт по пункту за тик, помечает тупики и идёт дальше,
пишет состояние каждый тик — включая пустой, отмечает закрытые пункты в
`PLAN.md`, кладёт находки не по своей части в `BACKLOG.md`.

**Не делает:** не переписывает план, не переставляет разделы, не решает, какая
очередь действующая, не пишет в боевые данные, не заходит в закрытые зоны.

---

## Честно о границах

Это **правила для модели, а не механические ворота.** Разница существенная: в
соседнем инструменте `proverka` три исхода — буквально коды возврата, и есть
самопроверка, ловящая одиннадцать подложенных порч. Здесь то же самое держится
на дисциплине модели в неприсмотренном прогоне. Проверяющего снаружи нет.

**Прогон не может сообщить о собственной смерти.** Закрылся терминал, упала
сессия, истёк семидневный потолок расписания — узнать можно только придя и
посмотрев. Хотите надёжнее — поставьте снаружи сторожа на время правки файла
состояния: не рос два шага подряд, значит прогон мёртв.

**Расписание живёт, пока жива сессия**, и само снимается через 7 дней.
Пропущенные тики не догоняются.

## Происхождение

Собран в работе с ИИ-агентами на живых проектах в 2026 году и переписан после
прожарки тремя специалистами: что сломается вживую, что лишнее, чего не хватает
постороннему. Переписанная версия **короче на 17%** и при этом содержит семь
исправлений, которых не было.

Самое дорогое из найденного — команда коммита, которая падала ровно в том
случае, ради которого написана: новый `BACKLOG.md` git ещё не знает, `commit`
без `add` возвращает код 1 и уносит с собой правку плана. В замере на живых
проектах это 25 случаев из 37.

Каждое правило внутри стоит за конкретным случаем. Личных данных нет.
